# RESEARCH 调研 · 诗文排版参照与落地规则（2026-11-04）

> 起因：用户反馈「不同类型的诗词排版观感不好，不够工整」，要一批软件/网站的排版方案作参照。
> 本文档交付两件事：①外部参照清单（每家能偷什么）；②分体裁的排版规则草案（待用户过目后定案入 DECISIONS）。
> 结论先行：现行地基（等长联句合行＋居中柱＋长诗降字号）是课本/选本的正体，方向不用推翻；
> 观感差集中在三处——**词曲句子被机械拆成 3~6 字碎行、章/片/段层次不可见（章距=行距）、
> 行尾全角标点把居中中轴拉偏**。修复都在 `PoemLayout.kt` 一个文件内可完成。

## 一、现状定位（对号入座）

逐条对照 `app/src/main/java/com/jigu/app/ui/detail/PoemLayout.kt` 与手感问题：

| # | 现象 | 代码位置 | 根因 |
| :-- | :-- | :-- | :-- |
| 1 | 词碎行：「转朱阁，／低绮户，／照无眠。」三行各 3 字 | `paragraphToLines` 只合并「恰好两段等长」的句（L39-42），三逗句、不等长句全部落 else 分支逐逗拆行 | 长短句体裁被当成近体处理 |
| 2 | 词不齐：「不应有恨，／何事长向别时圆。」前短后长断开 | 同上：6+7 字不等长即拆 | 同上 |
| 3 | 诗经五章看不出「章」，「行距=章距」 | `PoemBody` 外层与内层 `spacedBy(6.dp)` 同值（L88-89） | 段落间距没有层级 |
| 4 | 每行视觉重心偏左（行尾「。」拖住轴心） | `textAlign = Center` 按字形盒居中，全角行尾标点右半空格占一格 | 未做视觉校轴 |
| 5 | 小序/长段裸文本夹在居中柱之间，体量突兀 | `lines.size > 10` 回退左对齐整段 Text（L94-100） | 序没有独立层级（字号、缩进、间隔） |
| 6 | 古文不缩进，贴边通读略糙 | PROSE 分支纯左对齐（L64-75） | 无段首缩进 |
| 7 | 词上下片之间无标记（水调歌头上下阕连排一片） | 数据层 `paragraphs` 每段＝一个句读组，**片界不在数据里**（下文已验证） | 需词牌规则表或人工标注，属远期 |

数据结构核验（2026-11-04 打开数据集实查）：

```
宋词 ci.song.*/宋词三百首.json : paragraphs[ i ] = 一个句读组（「明月几时有，把酒问青天。」）
元曲 yuanqu.json               : 同词，每段一个句读组
诗经 shijing.json              : content[ i ] = 一章（关雎 5 章 → 5 段）※ 键名是 content 不是 paragraphs
楚辞 chuci.json                : content[ i ] = 一句（离骚 189 段）
论语 lunyu.json                : paragraphs[ i ] = 一章（章内含引语长句）
```

→ 词曲「整句成行」、诗经「章距分层」、楚辞「逐句合并」都能零成本落地；
→ 词的**片界**必须补词牌数据才有，先不做。

## 三、分体裁排版规则（草案，待定案记 D-0xx）

判定依据：`category`＋现有 `paragraphToLines`；改造集中改 `PoemLayout.kt`。

### 1. 近体诗（绝句/律诗，五言/七言）——保持现状＋一处微调

- 「X，Y。」等长双句合一行、居中柱：**保留**（课本正体，西窗烛同路）。
- 新增**视觉校轴**：行尾以。？！收尾的行整体左移半字（0.5×fontSize），把标点空格让出，字体重心回轴——一行代码级别的` offset`（见四-1）。
- 长诗自适应降字号逻辑保留；下限 18sp 建议抬到 20sp（Merz 21 Note 屏大，18 偏小感明显——真机验收定夺）。

### 2. 词（宋词、五代词、纳兰）——改动最大

- **每句读组整句成行**：`paragraphs` 每段本来就是一个句组（已核数据），不再拆逗；「转朱阁，低绮户，照无眠。」整体一行、行尾句号收束——即通行选本与龙谱的**韵断分行**。
- 行宽=Math.min(plainLen+标点格数)：仍走 `poemFontSize` 自适应缩字号；单句 plainLen>24 的长调 fallback 才逐逗拆行（兜底）。
- 现行 16 字合并上限对**词放宽到整句**（词行 7~17 字常态，25sp 下最长 17 字行仍可容纳）。
- **片界**：数据无片标记，先不做；远期做「常见词牌上片句数表」（仅宋词三百首 325 首可人工标注），到位后上下片之间空一行（依宋词排版惯例：横排空一行或空两格）。

### 3. 曲（元曲）——顺着词走

- 曲牌衬字使句长参差：同样整句成行＋自适应缩字号；不做衬字标注（成本高、观感收益低）。

### 4. 诗经——加层距

- 每章的「关关雎鸠，在河之洲。」合行不变；**章距=2.5×行距**（外层 spacing 从 6dp 分离，外层约 20~24dp、行距 6~8dp）——章的结构感立刻出来。
- 章号「一章/二章」小字注：不做（视觉层已够，加号反而繁）。

### 5. 楚辞——逐句成行

- 数据每段一句（已核）；沿用等长合并（「…兮，…。」双句成行）；离骚 189 句走长诗降字号。
- 章界无数据，不做。

### 6. 小序/长段（>10 行 fallback）——给序一个身份

- 字号小一档（正文 25 → 序 20~21）、左对齐 + **首行缩进两字**、与正文间隔约 1.5 行——古籍「序以小字冠前」的惯例；不再裸贴。
- 判定沿用现有 `lines.size > 10`，先不引数据层 has_preface 标记（成本高，观感收益小）。

### 7. 古文/语录/蒙学——补缩进与节律

- 段首缩进两字（首行 `textIndent` 效果，Compose 用 inlineContent 或在段首拼「全角空格×2」）；行距现行 44sp/25sp≈1.76 略松，建议 1.6~1.7。
- 论语每段=一章（数据已核），章间空行自然由段落间距给。

### 8. 名句卡/今日页——不动

- 两句型名句按标点断行的现行做法（D-016）就是「每日推荐」的通行式（西窗烛同），保持。

### 9. 竖排——同步受益

- 整句成行后竖排列长更均匀；诗经章距同样放列距；片界远期同步（空半列）。

## 四、Compose 落地技术要点

### 1. 行尾标点视觉校轴（便宜且收益大）——已实现（2026-11-04 落地注记）

- 全角标点字形占 1em 但「。」等字形墨迹在字面左半 → 行尾标点把文字重心向左拖半字。
- 居中柱上：**行尾是。/！/？/：/；等句读的行，整体 `offsetX = +0.25×fontSize`**（右移 1/4 字，
  补回标点右半空格造成的观感偏移，与居中标题的墨迹中轴对齐——原稿误写「左移半字」，纯水平推导勘误）。
- 不用测宽、不用自定义 Span；真悬挂不做（clreq：中文出版界主流不悬挂）。验收用「静夜思/水调歌头/关雎」三首对比截图看轴。

### 2. 层次 spacing 的实现

- `PoemBody` 外层 `Column(verticalArrangement = spacedBy(6.dp))` 改为：行距 6.optimal、段距/章距 22dp 分离；即每段自带一个内层行 Column，外层统一放段间距——近体诗（一段=一联行）看不出变化，诗经/组诗/小立层级。

### 3. 避头尾

- 自拆行是预断好的一行一个 Text，不会折行；长 Text 兜底折行走 ICU 断行，Android 默认已执行中文禁则（。？在行首不出现）——**不新增工作**，别自研。

### 4. 诗与文段落缩进差异化

- PROSE 段首缩进：段前拼接字符方案（两枚全角空格）最简，但会污染选中/复制文本——若在意则改用 `ParagraphStyle`/首行 padding；先取拼接字符方案验收观感（离线只读 App，「复制带空格」可接受，D-021 可议）。

## 五、建议落地顺序

1. **P排-1**：词曲整句成行（放宽合并规则）＋ 诗经/楚辞/组诗的段落层级 spacing——观感收益最大，全部在 `PoemLayout.kt`。
2. **P排-2**：行尾标点视觉校轴（-0.5em）——一行代码。
3. **P排-3**：小序缩进小字块 ＋ 古文段首缩进、行距 1.6~1.7。
4. 远期（已有架位）：词牌片界/韵脚标注（搜韵式）、图文对照（识典式）、注释/评点混排（雅言 F 架位＋PoetryType 思路）、纸纹质感（既有待办）。
