# 需求分析与路线图（2026-11-19，用户访谈定稿）

> 来源：本场「从零开始」需求访谈（8 轮选项问答，用户本人口述裁定）。
> 定位：本文是产品需求的事实源；实施时按模块立 D-043+ 决策条。与既有 D-001~D-042 冲突处，以本文为准。

## 一、访谈揭示的核心矛盾（此前所有"不对劲"的根子）

| 维度 | 用户内心答案 | 产品现状 |
|---|---|---|
| **灵魂功能** | **搜索与查找**（记得一两句找全诗/想看某诗人/记得内容不记得题名） | 书架导航 + 日推为主干，搜索只是功能 |
| 日推的角色 | 情感入口（每天 1-2 分钟小确幸），**不是**产品主干 | 与书架并列的第一屏主体 |
| 目标使用感 | **四种形态并用**：日推=内容氛围 / 诗词搜索=工具 / 古文=阅读器 / 书库=看诗人 | 一种形态（书架导航）硬套所有场景 |
| 首页 | **极简一句话**（参照「几枝」），非书架、非名篇流大卡 | 书架 + 今日诗卡 |
| 内容痛感 | 不是量，是**命中率**；但本轮仍愿数据优先 | 持续堆量却无入口聚合 |

结论：**汲古不是"书架 App"，是"一个随手可查的诗词古文工具 + 被喂诗的生活仪式"**。
此前反复改书架/分类/卡数，是在给错误的中心打补丁。

## 二、产品定位修订

一句话定位（修订）：
> 一天一句诗，跟着节气过日子；**想找的时候，一句记不全也能找到它**。

四形态模型（一机四貌，按场景切换，不做统一信息架构）：

1. **每日形态**（内容型·几枝式）：一句话、极简、切句、时间线历史、情境化推送。
2. **查找形态**（工具型·词典式）：搜索即入口，作者/名句/诗文书名全命中，结果可排序。
3. **古文形态**（阅读型）：像阅读器一样读整本（目录跳转/进度/沉浸）。
4. **书库形态**（诗人型）：以"诗人"为第一公民，随时看喜欢的人和他的作品。

原则修订：**"全离线"→"默认全离线，天气情境可选项联网"**（用户已拍板，D-043 立条时同步修订 D-001/定位文案）。

## 三、需求规格（按用户拍板的优先级）

### R1 搜索升级（本轮，P0）
- 命中范围：**正文任意片段**（几个字即可，容忍句读差异）＋**诗人名**＋**名句**＋**书名/篇名**。
- **诗人名命中 → 作者卡置顶**（修「搜到柳永的词、搜不到柳永的人」）：卡片含 姓名/朝代/身份/作品数，点击进诗人主页；下方才是他的作品。
- 名句命中 → 显示名句并直达**原诗全文并高亮该句**。
- 排序：**匹配度 × 名气混合**（标题命中升权；名气用现有 popularity 数据，不另建）。
- 验收：搜「柳永」出作者卡→主页；搜「衣带渐宽」出原句+高亮定位；搜「逍遥游」直接定位篇目。

### R2 诗人主页 + 关注（本轮，P0）
- 诗人主页四件套（用户全选）：**生平小传**（3-5 行内）、**全部作品按体裁/词牌/时间分组**（作品散在多卡必须聚合到人）、**名篇名句置顶**、**可关注**。
- 关注机制：独立「我关注的诗人」列表页；今日诗选取对关注诗人**适度加权（不要过大，主体仍是全库）**。
- 顺带满足"别集不全"的真实含义：不是缺作品，是**缺聚合入口**（作品散在全唐诗/全宋词/乐府/元诗等卡里找不到人）。
- 验收：关注柳永→列表可见→今日诗偶有加权；主页可一路翻完他的全部作品。

### R3 首页「几枝化」（大改，先小步后动）
- 首屏=**每日一句**：只展示句子（含出处小字），界面极简；**不合集中文/图卡**。
- 切句交互：**左右滑动+「下一句」按钮并存，手感以按钮为准**（用户原话：左右切换手感怪）。
- **点句子 → 跳全诗详情**；返回继续切句。
- **推送时间线**：按天倒序回看过去几日/几月推送过什么（即"我的诗历"的基础形态）。
- 搜索入口前置且显眼（首页即可搜）。
- 推进方式：先小步（搜索/诗人页先行）→ 验证后再动首页大改。

### R4 情境化推送（P1，含联网拍板）
- **可选联网天气**：开关开启后每天拉一次天气+粗略定位，按天气配诗；关闭即纯离线。
- 季节/节气/时辰为基础维度；**季节×心情池** + **「最近状态」模式**（备考/低谷/退休等持续偏向）两者都要（用户选 1+2 结合）。
- 「鼓舞人心的诗」为可触发情绪类之一。
- 推送形式：系统通知（早/晚可设）+ 首页时间线；**不做朗读（D-013 维持否决）**。

### R5 名句体系（P1）
- 名句可**单独浏览/收藏**（名句库/名句榜）。
- 搜到名句→原诗高亮定位。
- **四书五经名句按书/篇组织**（引用场景）；复制带出处（作者·篇名）为附带项。

### R6 我的诗历（P2）
- 时间线形态为主（同 R3 推送时间线）；收藏按日期归档回看。

### R7 详情页排版（P1，视觉第一优先项）
- 优先级：**标题层级感 + 字号行距 + 页边留白/纸感**（用户选三，未选"长文分页"——保持滚动）。
- 不做：应用图标另行对话（用户拍板本场不定）。

### R8 古文阅读器化（P2）
- 篇内目录/章节跳转、继续读进度、沉浸阅读感（参照阅读器，非 App 流）。

### R9 书库自选置顶（P2）
- 书架卡**自选 pin**，其余收进「全部书库」；诗人优先入口在诗人群（R2）内解决。

### R10 数据扩容（本轮，用户拍"数据优先"）
- 大块头先行：**史记全本**（四库夹注可剥类）、**大部头古籍缺口**（用户点名类：五经/资治通鉴等候选需补调查）、**全唐诗补编二期 ~5,700 首**。
- 原则不变：D-010/整本条例、verify 校验环、数据版本递增。

## 四、路线图（用户拍板顺序）

```
第 1 轮：数据优先（R10）+ 诗人主页/搜索升级（R1/R2）先行小步
第 2 轮：首页几枝化（R3）——信息架构手术，一次到位的验收点
第 3 轮：情境推送+天气（R4）、名句体系（R5）、详情页排版（R7）
第 4 轮：古文阅读器化（R8）、书库自选（R9）、诗历（R6）
```

## 五、与既有决策的关系

- D-001 定位文案："无信息流、全离线"维持（推送时间线是**自己的历史**，非信息流）；天气为可选联网例外。
- D-007/D-020 日推配额：偏好维度从"题材"扩展到"季节×心情×关注诗人权重×状态模式"，机制复用 `PoemOfDay.pick` 池。
- D-028/D-030/D-032 书架系列：**停止以书架为中心继续微调**；书架降级为第二入口（R9）。
- D-013 朗读：维持否决。D-011 赏画：已终止（D-040）。
- D-012 署名规范：诗人主页与搜索作者卡复用同一署名出口。

## 六、验收总则

- 每个模块交付 = 构建包 + 分步验收清单（真机，用户本人执行）。
- 每轮结束更新 AGENTS 现状摘要；实施决策立 D-043 起编号。
