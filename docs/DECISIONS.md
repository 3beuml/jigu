## D-001 产品定位（2026-10-24）

一句话：**诗词版岛读——一天一首，跟着节气过日子；把诗送进生活，而不是把用户拉进 App。**

## D-017 缺字占位（□）处理规范（2026-11-01，用户报"部分显示方框"定位后定案）

- **根因不是字体**：863 个 Ext-B+ 嫁接字形真机渲染正常（𫜪/𩻣/㐷 已真机验证）；库内可展示文本对子集字体覆盖完整（`tools/fonts/check_font_coverage.py` 全量核对，空字形 0、悬空组件 0）。
- "方框"实为数据集自带的 **U+25A1「□」缺字占位符**（碑损/阙佚标记，全库正文 12124 个、标题 410 个、作者名 46 个），渲染出来形同豆腐块。
- 处理分三层，**不虚构内容**：
  1. **标题**：纯占位（题根全为□，含「·其N」序号与「・词调名」尾）→ 归「**佚题**」（`build.py clean_placeholder_title`，25 题）；部分缺字（「□后圃成三绝句」「元□□」）**保留校勘原貌**。
  2. **作者名**：全部为部分缺字（李□/元□□，姓存名佚），有校勘信息量，保留不动。
  3. **正文**：□ 是缺字校勘惯例（"□□□□□□□，□□□□"= 李煜残句），保留。
- 名句池同步排除「佚题%」（原排除 '%□%' 因改名失效）；`check_font_glyf.py`/`check_font_coverage.py` 为长期自查工具，字体或数据改动后必跑。

## D-018 日推轮转序：时代打散（2026-11-01，用户报"每日推荐全是清代"定案）

- **根因**：`PoemsDb.curatedAtOffset` 用 `LIMIT/OFFSET` 却无 `ORDER BY`，轮转指针按 rowid 爬
  数据源连片——精选池 1415 首中「清」477 首连成一片（qing_ci 258 + youmengying 219），
  连续多天与同日「换一首」全部落在清（实测模拟：2026-11-01 起连续 10 天全清）。
- **修复**：精选池序改为**固定种子整体洗牌 + 同时代连片>2 修复**（`PoemsDb.curatedOrder()`，
  纯函数 `breakEraRuns` 可单测）。洗牌序确定可复现，进程内与跨重开一致；
  D-006 的"同一天任何时候打开都是同一首"与 D-011 的"换一首顺位后移、重开不变"语义不变。
- **保留的分布事实**：池内清占 34%（清词 258 + 幽梦影 219）是陈列层选本构成，洗牌只打散
  不加权——清约每 3 天出现一次属正常；若要压低，需在 D-008 陈列层选本上做池级取舍（另行定案）。
- **已知遗留**：节气/节日配诗池（calendar_map）多为唐 20 首连片选材（情境契合优先），
  池内按 id 轮转，节气日永远唐诗——待后续按意象+时代混合重配。
